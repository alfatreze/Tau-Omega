Facts about Tau come from `docs/features/ART_SIDECAR_SPEC.md`, `TRACK_DETAILS_SPEC.md`, `fw/replaygain.h`, `fw/player.c`, `tools/sync_media.py`, `tools/tau_library.py` and `tools/tau_details.py`; Omega facts from the code, checked by running it. ## 2. Do we transcode today? Answer: no audio, and almost nothing else
- **Audio is never decoded, re-encoded or resampled.** MP3 and FLAC are copied byte for byte (SHA-256 before and after). Anything that is not `.mp3`/`.flac` (M4A/AAC/ALAC, WAV, AIFF, OGG, Opus, WMA) is skipped; the Library page lists it as unsupported.
- **Files that are changed on the copy** (the source is never touched): (a) *cover embedding*: a baseline JPEG is written into the copy's ID3 tag or a FLAC PICTURE block (existing frames and all audio bytes kept; progressive JPEG and PNG are refused, the songs are copied without the cover and a warning is shown); on by default on the Library page. (b) *tag edits* the user asks for in the workbench. (c) *names*: folded to ASCII and refused on collision.
- **Images are converted:** cover sidecar `cover_128.pal256.timg` (the cover is scaled to 128 px on the long side and reduced to 256 colours). That is the Tau format, not a copy of the picture.
- Tau's own Python tool differs in two places: it converts PNG/progressive covers to baseline JPEG (macOS `sips`) before embedding, where Omega refuses; and it makes sidecars from embedded art, where Omega does not. Neither tool re-encodes audio.

## 3. Adjustments to make (ordered)
1. **Sidecars on by default, from any cover source** (replaces "opt-in"): engine default on, CLI default on with `--no-art-sidecar`, same source order as Tau's tool (`--cover`, named folder image, art embedded in the first track that has any (MP3 APIC, FLAC PICTURE), any image in the folder or one level below, front/cover names first then the largest), idempotent (skip when the existing sidecar's source hash matches, record the hash like the ledger does), loose tracks get a sidecar in their own folder. Fixture: Tau's real `cover_128.pal256.timg` already in `testdata/`; add an embedded-art-only album and compare with `tools/sync_media.py --art-variants` output byte for byte.
2. **Size set as data, not code:** an Omega-side table (use, size) mirroring Tau's planned `art_sizes.json` (never the same file, per the cross-project rule); until Tau settles it, one entry (128). The index flag (sidecar present, later a size bitmask) follows when Tau freezes it.
3. **Refresh / health for albums already on the card:** "N albums have no cover file" in the health badge, and a Refresh step that creates the missing sidecars (reviewed plan, same write path as other changes).
4. **Index details section writer** (port of `tools/tau_details.py`: codec, rate, channels, depth, bitrate, VBR, encoder, LAME delay/padding, ReplayGain, embedded cover size, sidecar flag), byte-identical to `tools/tau_library.py` on real files (fixtures generated by the reference tool, as for TPG and PRST). Until it exists, Omega should **keep an existing details section** when it only adds or removes albums? Not possible (records are per track); so say so in the sync review ("this index will not carry track details") rather than drop it silently.
5. **ReplayGain: show and protect first, create later.** Read the four tags (TXXX/Vorbis) when scanning; show "ReplayGain: complete / partial / none" per album in the Library; a problems category (info level) for an album with track gain but no album gain, or gain without peak (no boost on the Pocket); a test that a cover embed and a tag edit keep TXXX RG frames and Vorbis RG comments. Creating tags is section 4.
6. **Read sample rate, bit depth and channels** from MP3 frame headers and FLAC STREAMINFO (cheap, no decoding) and flag files the Pocket refuses (FLAC above 48 kHz, more than 2 channels, depths the decoder does not support) as "will not play on the Pocket" with the reason, in the Library page, Problems and the sync review.
7. **Embedding default:** with sidecars mandatory, embedding the cover into every copied track (a tag rewrite of the user's files) is no longer needed for the Pocket. Recommend default **off** ("also embed the cover in the copied files, for other players"); keep the code. Needs the owner's OK because it changes current behaviour.
8. Docs: add Omega's row to `CROSS_PROJECT_INTERFACE.md`'s watch list (sidecar sizes, details section) on Tau's side only via a note to the owner.

## 4. Transcoding plan: defaults and settings (proposal, nothing built)
**Principle:** the Pocket plays what it plays. Files are copied as they are; conversion exists only to make an otherwise unplayable file playable, never as a quiet side effect, never in place, and always shown before it runs.

**Sync settings (one "Sync" section in Settings, per-run override on the sync review):**
| Setting | Choices | Default | Notes |
|---|---|---|---|
| Music the Pocket can play | Copy unchanged | **always** | MP3 and FLAC within limits are never altered. Not a choice. |
| Music the Pocket cannot play (hi-res FLAC above 48 kHz, more than 2 channels, M4A/ALAC, WAV, AIFF) | **Skip and list** / Convert to FLAC | **Skip and list** | Convert (lossless source to FLAC): hi-res is resampled to 48 kHz (or 44.1 kHz for the 44.1 family) with a high-quality resampler, depth kept up to 24-bit, channels folded to stereo with a stated rule; ALAC/WAV/AIFF become FLAC unchanged in sample rate/depth when already within limits. Tags, cover and ReplayGain are carried over, then **peak recomputed** (resampling changes it; gain does not). Shown per album with size and time estimate before it runs; originals never changed; converted files are marked in the ledger/provenance and listed in the report. |
| Lossy formats the Pocket cannot play (AAC/M4A, OGG, Opus, WMA) | **Skip and list** only | Skip | No lossy-to-lossy conversion offered (generational loss, and there is no licence-clean MP3 encoder in pure Rust: LAME is LGPL C code). A user who wants them converts them elsewhere first. |
| Covers | Sidecar sizes: the table (default 128 now); embed into the copies: **off** / on | sidecar **on**, embed **off** | Non-baseline covers are converted automatically only when embedding is on (needs a JPEG encoder; see dependencies). |
| ReplayGain | **Keep existing tags** / Add missing (analyse and write) / Off (do not touch) | **Keep** | "Add missing" only for albums with no gain tags; track and album gain and peaks to the ReplayGain 2.0 reference (-18 LUFS), album-aware, written into the copies only, shown in the review as "tags will be added to N files". Never overwrites existing tags unless the user picks "Recalculate". |
| Names | ASCII fold | **on, not optional** | The player cannot open other names (issue 001). |
| Normalise loudness (change the audio) | not offered | n/a | ReplayGain does it without touching the audio. |

**Every run reports:** files copied unchanged, files converted, files skipped (with the reason), tags written, covers made. "Nothing in your files was changed" is the common, visible answer.

**New dependencies this would need (to approve one by one, none added):** decoding and resampling for convert (a pure-Rust decoder such as `symphonia`, resampler `rubato`), FLAC encoding (`flacenc`), loudness analysis for ReplayGain (`ebur128`), a JPEG encoder for embedding non-baseline covers (`jpeg-encoder`). Sidecars, details, the sample-rate/depth/channel checks and ReplayGain display need **no** new dependency.

**Order of work:** 1 to 3 (sidecars), 4 (details writer), 5 and 6 (ReplayGain display, rate/depth/channels), 7 (decision), then the optional Convert and ReplayGain-creation features as separate, individually approved steps.
