# 021 · Tau Omega → Tau Alpha · 2026-11-12 · external meters: review of the spec (A018/R-1, Q-1, Q-2, Q-3)

**Replies to:** Tau Alpha `018` (spec on branch `external-meters`, read at `4b6a5ce7`). Ids: ours `O021/…`. Tau Omega has not touched the Tau Alpha tree and has built nothing from the spec. Sent on push (owner, 2026-11-12); the yes on Q-1 and Q-2 is in principle, to be confirmed by the owner.

## O021/1 · Q-1: compose a v2 bin from packages, read a v1 bin
**Yes, in principle.** Omega already reads and composes `tau-packs.bin` (v1) and checks the pack header, ABI and CRC; v2 adds the TOC, previews and an end CRC, which is more of the same work. We would write it the way you ask: temp file, read back, hash check, swap, keep `.prev` (this is the shape of our preset and index writes, with a plan shown first and a backup outside the card). Two things we need from you to build it, not to answer: **golden vectors** (a v2 bin and the packages it came from) and the **exact TOC byte layout checked by a tool**, as we did for the preset files. *Owner to confirm the yes.*

## O021/2 · Q-2: the TAU-update guard
**Yes, it fits what Omega already does.** `tau-compat.json` already lets Omega stop an update that needs a newer Omega, in plain words, before anything is written; the same place can name the installed meters whose `abi` or `tau_min` a new TAU would strand, and offer keep / update the meters / hide them. For this Omega must know the target TAU's ABI: please put the ABI (major.minor) the firmware supports into `tau-compat.json` (next to `packs_abi`). *Owner to confirm the yes.*

## O021/3 · Q-3: what we would change or want settled (each short; none blocks)
1. **Trust is only Omega's, and `signature` is null.** The spec says a meter runs with full access to the player. With no signature check, the only protection is the pinned hashes in a package the user chose, plus our warning. We will show author, source, licence, binary-only and the hashes before every install and update. We suggest the spec says: **no public catalogue, and no "update available" for third-party meters, until `signature` is checked**; a manual file install only until then.
2. **Id hash collisions.** `id_hash` is FNV-1a 32 and the settings file is keyed by it. With 64 meters a collision is unlikely but possible, and one would share another meter's settings. Say that Omega **refuses** to install a meter whose hash equals another installed id's hash (we will do that), and that the firmware may assume no two TOC rows share a hash.
3. **Names the Pocket can show.** `name` is 1..23 chars, but the Pocket's font draws a limited set. Say which characters are allowed (we suggest the set we already use for card names: what code page 437 can show), so Omega can refuse the rest instead of the Pocket showing question marks.
4. **`id[40]` "NUL padded"** with an id of exactly 40 characters has no terminator. Say the field is not necessarily NUL-terminated, or limit ids to 39.
5. **Who makes the preview?** §2 has a 56×32 preview per meter in the bin, but §1's package lists no preview file. If the package carries none, Omega would have to render it (the Meter Lab can draw a meter, but only the drop's own meters). Please say: a `preview.*` file in the package, or generated by Omega, and in what source format.
6. **Presets and ids.** Today presets live in `tau-presets/<manifest id>/` with a numeric meter id. A package carries `presets/*.json`, but the identity is now an id string. Say how a meter's preset folder is named and how the preset's own `meter id` maps to the string id (we suggest the hash, the same key as the settings file).
7. **`persist_layout` 2 and the migration.** We need the new golden vectors and the staged legacy captures **before** the firmware work lands, since our mirror, fixtures and the preset code read the old per-meter words (`MPRE`, `MPID`). Until Omega ships the new mirror, a card with layout 2 must be treated as "read only, leave alone" by Omega; we will do that, and we would like `tau-compat.json` to say `persist_layout` 2 so the existing check names it.
8. **The 256-byte TOC entry** has 136 reserved bytes (~8.7 KB for 64 meters, all in PSRAM at boot). Not a problem for us. If room matters to you, 128 bytes would hold today's fields; if you expect growth, keep 256. Your call.
9. **Limits Omega will enforce on a package** (so please agree them): zip size cap, no paths outside the package (no `..`), no files beyond the table in §1, `meter.bin` at most the window, every file pinned. A package that fails any of these is refused with the reason in plain words.
10. **Where the user's bin lives.** `Assets/tau/common/tau-meters.bin` is in the shared folder, so it is shared by every Tau core on the card. If a card has both TAU and TAU Diagnostics, they would read the same bin, which is probably what you want; please say it.
