A new drop that renames any of them breaks the Common tab, the Details panel or the budget bar (the preview and `tau-lab-set` keep working). ## Findings from doing it
- **O014/F-4: a fractional scale makes the bars glitch.** The lab draws a 400 x 360 canvas with `image-rendering: pixelated` and `max-width: 100%`. In a frame a few pixels narrower than 400 css px the picture is scaled by about 0.99 and nearest-neighbour sampling gives uneven bars and black slits. Omega now never scales it (fixed 400 css px). You may want the same guard in the lab itself. The 1 px canvas border also adds 2 px to the displayed width.
- **O014/F-5: your cost window is 120 frames.** `costs` keeps the last 120 frames (about 3 s) and is only cleared by `setup()`; a parameter change goes through `params = p` without a reset, so the `#cost` figures take about three seconds to follow a change of setting. Omega's budget bar therefore reads the last second instead (about 45 ms to react to a rise, up to a second to fall).
- **O014/F-6: the full-screen figure is generic in the lab.** `fullfig` changes `box` for every meter; `caps` in `meters_schema.json` are hardware flags (`bar`, `sblit`, `hw_spectrum` ...), none says whether a meter has a full-screen view.

## Requests
- **O014/R-1: a native embed mode in the lab.** For example a URL fragment or a `tau-lab-embed` message: no heading, no panel, no parameter list, transparent background, no sticky stage; the page reports the size of the meter view. This would remove F-1 and the sizing part of F-2.
- **O014/R-2: an options message for the preview controls.** `tau-lab-options` (lab to embedder: the list, each with id, label, type, choices or range, current value, which meters it applies to) and `tau-lab-option` (embedder to lab: id, value). This would remove the element-id coupling in F-2 (a) and let you say which options apply to which meter (today Omega hard-codes `barready` for Winamp Bars, `timedg` for Layered Wave, `statsok` and `corr` for Sound Map).
- **O014/R-3: the detail area as data.** `tau-lab-info` with the cost summary as fields (mean, worst, allowance, class, verdict, cell width, CPU range, engine pixels) and the per-option table as rows and cells, instead of text that Omega parses by its wording (a line Omega does not recognise is kept as a plain note, so a rewording degrades, it does not break).
- **O014/R-4: per-meter view data.** Whether a meter has a full-screen view, and the rectangle each view draws in (small: `x, y, w, h`; full-screen), in `lab-data.json`, so Omega does not hard-code the crop. Omega needs the **Small view / Full screen toggle for every meter that has the full-screen view** (owner's requirement); today it offers it for all.
- **O014/R-5: a per-frame cost message.** `tau-lab-cost` every frame or every other frame with the current frame's command count and the window you judge by, so Omega does not need to hook `TauCost.summarize`. Please say which window the allowance verdict is meant to use (your page uses the worst of the last 120 frames).
